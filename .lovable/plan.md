## Goal

Make the borrow request flow demo-ready: real notifications to both sides, a deep-linkable request detail, approver-focused filtering, partial approvals, cancel, and borrow history — usable by Manager, Warehouse Manager, and Admin (Engineers stay read-only).

## Current state (verified)

The borrow request itself works (create, approve/deny, stock transfer), and there is a Notifications page plus a bell in the header, but **no notification is ever created for a borrow request** — the table is always empty. The database rule also only lets a user insert notifications addressed to themselves, so the browser cannot notify the other project's manager.

## 1. Notifications generated by the database

Add a trigger on borrow requests so notifications are created reliably and can be addressed to other users:

- **On create** → requester gets "Your borrow request was sent to <source project>"; the source project's manager(s) get "<Target project> is requesting N x <part> from <source project>".
- **On decision (approved / partially approved / denied)** → both the requester and the deciding side get the outcome, including approved quantity and any note.
- **On cancel** → the source project's manager(s) are told the request was withdrawn.
- Recipients = the project's assigned Project Manager plus anyone assigned to that project as manager, de-duplicated; plus admins and warehouse managers so oversight roles see activity too. The person who caused the event isn't notified twice.
- Every notification stores a link straight to the specific request.

## 2. Deep link + approver-focused Borrow Requests page

- Each request gets a detail panel reachable by link (`/borrow-requests?request=<id>`) showing requester, date, reason, needed-by, source on-hand, decision, decision note, and the resulting stock movement.
- Notification "Open" navigates there and marks that notification read.
- Tabs: **Needs my approval** / **My requests** / **All**.
- Approve, Deny and Cancel buttons only render for users who can actually act.

## 3. Decisions and permissions

- Approve dialog with an editable approved quantity (enables partial approval) and an optional note; approving less than requested records "partially approved".
- Approval blocked above current source on-hand, with a clear message.
- Requester can **cancel** their own pending request.
- **Who can do what:**
  - Manager — create requests for their projects; approve/deny requests against projects they manage.
  - Warehouse Manager — create, approve and deny for any project.
  - Admin — same as Warehouse Manager, unrestricted.
  - Engineer — read-only, no create/approve/deny.
- Database access rules updated so Warehouse Managers and Admins can create and decide on any project's borrow requests, matching the UI.

## 4. Live bell

Subscribe to new notifications so the header unread count updates without a refresh — useful when demoing two accounts side by side. (Email notifications are explicitly out of scope.)

## 5. Borrow history in context

On the project detail page and the inventory view, show borrow movements for that project (borrowed out / borrowed in, with quantity, counterpart project and date) so it's obvious where stock went.

## 6. Fix the test data

Project 2601 has a Project Manager set on the project record but no matching project assignment, so that manager currently can't see or act on 2601. Assign them, and keep the Project Manager field and the assignment table in sync going forward.
